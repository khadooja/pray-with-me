# دليل الفريق 🤝

هلا والله! هذا الملف يشرح كيف نشتغل أربعتنا على نفس المشروع بدون ما نخرّب على بعض.
الفكرة ببساطة: كل وحدة لها **ملفات تملكها**، وفيه **عقود** (أشكال بيانات ثابتة) بين الأجزاء. طالما العقد ما تغيّر، كل وحدة تقدر تشتغل براحتها.

## التشغيل

تحتاجين Node.js 18 أو أحدث.

```bash
npm install
npm run dev                      # افتحي http://localhost:5173/
npm test                         # كل الاختبارات (١٠ ملفات في tests/، Node عادي بدون أي framework)
npm run build                    # لازم ينجح قبل أي دمج
node scripts/build-content.mjs   # يعيد توليد fajr.json و SOURCES.md من ملفات المحتوى
```

- `/?mock=1` ← وضع تجريبي: نتائج وهمية للوضعيات والتلاوة، بلا كاميرا ولا مايك ولا تحميل نماذج.
- `/labs/pose.html` ← مختبر الوضعيات (لضبط الأرقام).
- `/labs/speech.html` ← مختبر التلاوة (لقياس السرعة وتجربة النماذج).
- `/labs/figure.html` ← مختبر الشكل التوضيحي (كل الوضعيات والانتقالات في صفحة واحدة).
- `/labs/results.html` ← نتائج اختبار المستخدمين (محاولات هذا المتصفح + تصدير CSV/JSON).

الكاميرا والمايك يشتغلون بس على `localhost` أو `https`.

## العقود (لا تغيرونها بدون اتفاق الكل)

**الوضعيات:**
```js
evaluatePose(landmarks, stepId, aspect) // → { ok: boolean, issues: string[] }
```
- `issues` أكواد أخطاء مثل `"knees_bent"`، ونصوصها موجودة **بس** في `src/i18n/en.json`.

**التلاوة:**
```js
compareRecitation(transcript, reference) // → { complete, missing: string[], orderOk, matched, total }
```

**المحتوى:** ⚠️ `src/content/fajr.json` **مُولَّد** — لا يُعدّل باليد أبداً (شوفي قسم المحتوى تحت).
كل خطوة فيه فيها `id` و `type` (`guided` / `pose` / `speech`) و `title {ar, en}` و `level`
(`rukn` / `wajib` / `sunnah`) و `instruction {en}` و `source` و `sourceRefs` (أرقام المصادر).

- حقول اختيارية للخطوة: `instructionLevel` (إذا كانت التعليمات نفسها سنة)، و`dhikr` فيها
  `{arabic, transliteration, meaning{en}, level, once?, audio}`، و`video` (مثلاً `"/video/ruku.mp4"`).
- خطوة `pose` لازم يكون فيها `check` (`standing` / `ruku` / `sujood`).
- خطوة `speech` (الفاتحة) فيها `reference` (بدون تشكيل، وهو النص اللي يُفحص) و`verses` (كل آية
  بعربيها ونطقها ومعناها) و`sunnahVerses` (البسملة والتأمين — سنة، وما تدخل في الفحص أبداً) و`audio`.
- تكبيرتا الانتقال (`takbir_to_ruku` و`takbir_to_sujood`) فيهما `raiseHands` و`ruling` و`transitionFrom`.

وعلى مستوى الملف كله: `order` (ترتيب الرحلة — كل مدخلة إما اسم خطوة أو `{id, transition}`)،
و`transitions` (نص تكبيرة الانتقال، معرّف مرة واحدة ويُشار له من `order`)، و`sources` (خريطة
المصادر المرقّمة)، و`preparation` (عناصر شاشة "قبل أن تصلي").
`src/content/journey.js` هو اللي يحوّل `order` إلى الرحلة الكاملة (٢٤ موضع = ركعتان).

## مين يملك وش

### 📖 المحتوى: ليان العصيمي
**ملفاتك:** `docs/content-source.md` و `docs/preparation-source.md` و `public/audio/`

#### ⚠️ الأهم: `fajr.json` و `SOURCES.md` مُولَّدان، لا تعدّلينهما باليد

التعديل اليدوي عليهما **يضيع** مع أول بناء. مكان التعديل هو ملفاتك فوق، وبعدها:

```bash
node scripts/build-content.mjs
```

- `docs/content-source.md` = جدولك النهائي لخطوات الصلاة (الأسماء، التعليمات، الأذكار، النطق،
  المعاني، آيات الفاتحة، تكبيرات الانتقال، المصادر المرقّمة، وملاحظاتك).
- `docs/preparation-source.md` = عناصر شاشة "قبل أن تصلي" الستة.
- `scripts/content-source.mjs` و `scripts/preparation-source.mjs` يقرأون ملفيك **نسخاً آلياً**:
  ما فيه أي نص ديني مكتوب داخل الكود، فما يمكن يُكتب غلط أو "يُصحَّح" من أحد.
- `tests/content.test.mjs` يعيد قراءة نفس الملفين ويفشل إذا اختلف `fajr.json` عنهما **حرفاً بحرف**،
  وكذلك إذا ظهرت كلمة `TODO` للمستخدم في أي شاشة.
- **الاستثناء الوحيد:** في `SOURCES.md` كل شيء من `## Demonstration videos` ونازل **محفوظ كما هو**
  (جدول الفيديوهات وجدول البرمجيات والنماذج) — هذا الجزء يُعدَّل باليد ويبقى بعد البناء.
  أي شيء تضيفينه **فوق** هذا العنوان يُمسح مع أول بناء.

#### بقية القواعد
- كمّلي الحقول اللي فيها `TODO` (المصادر، النطق، المعنى، الصوت) في ملفات المحتوى.
- **لا تخترعين** أرقام أحاديث أو مصادر. إذا ما تعرفين المصدر خليه `TODO`.
- أي ملف صوت تضيفينه حطيه في `public/audio/` وسجّلي مصدره ورخصته في `SOURCES.md`
  (في الجزء المحفوظ). الصوت يُربَط فقط إذا الملف موجود فعلاً على القرص، وإلا يبقى `TODO` وما يُعرض مشغّل.
- **لا تكسرين:** أسماء الحقول، و`id` الخطوات، وقيم `type` و `check`. النص المرجعي `reference`
  يكون بدون تشكيل (وهو **ما يُعاد توليده**: يبقى كما هو لأن وحدة الذكاء الاصطناعي تعتمد عليه).

#### 🕌 شاشة "قبل أن تصلي" (`PREPARATION_SCREEN_ENABLED = true`)

ستة عناصر من `docs/preparation-source.md`: الوقت، الوضوء، الطهارة، ستر العورة، القبلة، النية.

- كلها `Reviewed: yes` (اعتمدتِها أنتِ) — **والمراجعة الشرعية المتخصصة لسه معلّقة**.
- حقول اختيارية لكل عنصر: `Detail (English)` (سطر صغير تحت النص)، و`Source 2` + `URL 2`
  (مصدر ثانٍ)، و`Link URL` (رابط خارجي).
- عنصر الوضوء فيه رابط فيديو على YouTube: **التطبيق ما يحمّل أي شيء من YouTube**، والرابط
  يُفتح في تبويب جديد فقط إذا ضغط المستخدم عليه بنفسه.
- الشاشة **تذكير فقط**: التطبيق ما يفحص أياً منها، وما نسجّل الاختيارات ولا نرسلها لأي مكان.

#### 🎬 فيديو الشرح (اختياري، لكل خطوة)

كل خطوة ممكن يكون لها مقطع فيديو قصير يطلع **فوق** بطاقة الذكر، مثل تطبيقات تعلّم اللغات.

- حطي الملف في `public/video/` وأضيفي في الخطوة داخل `fajr.json` الحقل: `"video": "/video/<id>.mp4"` (مثلاً `/video/ruku.mp4`). مقطع واحد لكل خطوة، بدون وقت بداية أو نهاية: قصّي المقطع قبل ما ترفعينه.
- خلي كل مقطع **قصير وأقل من 5 ميغا**.
- **المقطع لازم يكون فيه الصوت** (صوت المُعلِّم بالذكر). إذا المقطع اشتغل، نخفي مشغّل صوت الذكر المنفصل لأن المقطع فيه الصوت أصلاً. وإذا ما اشتغل المقطع أو ما حطيتي حقل `video`، الخطوة تشتغل مثل أول بالضبط.
- ما فيه تشغيل تلقائي: المستخدم يضغط زر التشغيل. وعنده زر إعادة وزر سرعة (1x و 0.75x). والفيديو يوقف تلقائياً لما تشتغل الكاميرا أو يبدأ التسجيل.
- لازم تسجلين في `SOURCES.md` (جدول فيديو الشرح) مصدر كل مقطع، وموافقة المُعلِّم، ومين راجعه.

**ضغط المقطع** (720p و H.264 و CRF ‏28، ويبدأ بسرعة على الجوال بفضل `+faststart`، وما يكبّر المقطع لو كان أصغر من 720):

```bash
ffmpeg -i input.mp4 -vf "scale=-2:'min(720,ih)'" -c:v libx264 -crf 28 -preset slow -c:a aac -b:a 96k -movflags +faststart public/video/ruku.mp4
```

**قص مقطع من فيديو أطول** حسب وقت البداية والنهاية (ويضغطه بنفس الأمر):

```bash
ffmpeg -ss 00:00:05 -to 00:00:12 -i long.mp4 -vf "scale=-2:'min(720,ih)'" -c:v libx264 -crf 28 -preset slow -c:a aac -b:a 96k -movflags +faststart public/video/ruku.mp4
```

> الأوامر بصيغة bash. في PowerShell بدّلي علامات الاقتباس المفردة حول `min(720,ih)` حسب الحاجة، وتأكدي من حجم الملف بعد الضغط (لازم أقل من 5 ميغا).

**للتجربة قبل ما تجهز المقاطع الحقيقية:** حطي أي ملف mp4 في `public/video/` وأضيفي حقل `video` في نسختك المحلية من `fajr.json` بس، ولا تدفعينه.

#### 🔌 مفتاح فحص التلاوة (`SPEECH_CHECK_ENABLED = true` حالياً)

النصوص المستخدمة للفحص هي `verses[i].arabic` من `fajr.json` كما هي، ومجموعها بعد التطبيع

- `/labs/speech.html` **يشتغل كامل دايماً** (هذا مكان القياس عندك)، وهو الصفحة الوحيدة اللي

  بفحص مو موجود. و`tests/speech-switch.test.mjs` يتأكد إن README يقول نفس قيمة المفتاح.

  شُغّل المفتاح** (أو من المختبر)، و**رخصته `TODO`**: لازم تتأكدين منها وتسجّلينها في
  `SOURCES.md` **قبل** ما نشغّل الفحص للمستخدمين.

- قاعدة السجود وأرقامها (`headBelowHipMargin`) **نسخة أولى بسيطة عن قصد**: تتحقق بس إن الرأس أوطى من الورك. اضبطيها بالمختبر قبل أي تطوير.



#### 🎤 تقييم مطابقة التلاوة

المشكلة: النموذج يقسّم ويدمج الكلمات، فالمطابقة كلمة بكلمة تقول "ناقصة" وهي مقروءة.
على تسجيل حقيقي **صحيح** المطابق الحالي يطلّع عدة كلمات على أنها ناقصة وهي كلها مقروءة.
الأرقام الحالية تطلع من `npm run eval:speech` — ما نكتبها هنا عشان ما تتعفّن مع أي تعديل
على `align.js` أو على الحالات.

**كيف تضيفين تسجيلاتك:**
1. سجّلي في `/labs/speech.html` وانسخي النص المسموع كما هو بدون تعديل.
2. افتحي `eval/speech-fixtures.json` وأضيفي حالة جديدة:
   - `kind`: `"real"` لنص خرج من النموذج فعلاً، `"synthetic"` لحالة صنعتيها بحذف كلمات.
   - `recited`: `"full"` إذا قرأتي الفاتحة كاملة، `"omitted"` إذا حذفتي شيئاً عمداً.
   - `expectedMissing`: الكلمات اللي **فعلاً** ما قُرئت، بإملاء المرجع في `fajr.json`.
     في الحالة الكاملة تكون `[]`، فأي كلمة يرجعها المطابق تُحسب خطأً عليه.
3. شغّلي: `npm run eval:speech`

**الجدول يطلع لك:** لكل طريقة مطابقة، كم كلمة قالت عنها "ناقصة" وهي مقروءة،
وكم حذفاً حقيقياً أمسكته وكم فاته. ولكل كلمة خاطئة يقول لك السبب:
- **absent**: حروفها مو موجودة في النص أصلاً → خطأ من النموذج، المطابقة ما تقدر تصلحه.
- **split/merged**: الحروف موجودة لكن بحدود كلمات مختلفة → هذي المطابقة تقدر تصلحها.

**الطرق الثلاث** في `src/speech/matchers.js` (ملف جديد، ما يعدّل `align.js` أبداً):
- `word`: الحالي، يستورد `compareRecitation` وينادينها كما هي.
- `word-merge`: يسمح بكلمة مرجع = كلمتين ملصوقتين من النص، والعكس.
- `char`: يحاذي الحروف ويلغي حدود الكلمات (`CHAR_MATCH_RATIO`).

⚠️ **القرار قرارك.** المطابق المستخدم (لما يُشغَّل المفتاح) هو `compareRecitation`، وتبديله
سطر واحد في `src/speech/index.js` تسوينه إنتِ بعد ما تشوفين الأرقام على تسجيلات حقيقية كافية.
الحالات الموجودة الآن ٤ فقط وثلاثة منها مشتقة من تسجيل واحد، وكلها من نموذج Whisper الأساسي
(مو من نموذج مدرّب على القرآن): تدلّ على الاتجاه، مو دقة. وما دام المفتاح مطفأ، ما فيه مطابق
يشتغل للمستخدم أصلاً.
#### 📁 تجربة المختبرات بملفات مسجّلة (بدل الكاميرا والمايك)

صفحتين المختبر فيهم خيار تحميل ملف من جهازك، عشان تعيدين نفس التجربة أكثر من مرة وتقارنين الأرقام:

- **`/labs/pose.html` ← زر "تحميل ملف فيديو":** صوّري فيديو بجوالك وهو على الأرض على جنبك (نفس وضع شاشة التجهيز)، وحمّليه. يتشغل في نفس عنصر الفيديو وتشتغل عليه نفس حلقة الوضعيات ونفس القراءة الحية.
  - زر **تشغيل/إيقاف مؤقت** وشريط تنقل: وقّفي على إطار معين (مثلاً أسفل السجود) واقري أرقامه. وإذا غيّرتي الوضعية من القائمة وهو موقوف، يعيد التقييم على نفس الإطار.
  - زر **"نسخ القيم الحالية"** ينسخ نفس الـ JSON اللي تشوفينه عشان تلصقينه في جداول `eval/README.md`.
  - إذا انتقلتي لملف ثاني أو رجعتي للكاميرا، المختبر يحرر الملف القديم تلقائياً.
- **`/labs/speech.html` ← زر "تحميل ملف صوت":** يفك ترميز الملف (16 كيلوهرتز، قناة وحدة، بنفس طريقة التسجيل المباشر) ثم يشغّل نفس التفريغ والمقارنة، ويطبع النص المسموع وعدد الثواني ونتيجة `compareRecitation`. استخدميه لجدول التسجيلات في `eval/README.md` (S01 إلى S05).
- **الملفات تبقى على جهازك:** تتقرأ داخل المتصفح بس، ولا تُرفع ولا تتخزن. وتسجيلاتك لا ترفعينها على git: مكانها `eval/recordings/` وهو مستثنى في `.gitignore`.
- الصيغ المدعومة تعتمد على المتصفح: الأضمن فيديو mp4 (H.264) وصوت m4a أو mp3 أو wav أو webm. ملفات `.mov` من الآيفون ممكن ما تفتح في كل المتصفحات، وإذا ما فتح الملف تطلع رسالة بالعربي.
- زر النسخ يحتاج `localhost` أو https (وفيه بديل بسيط لو ما اشتغل).

### تجربة المستخدم: ليان الزهراني

#### 📊 صفحة النتائج (`/labs/results.html`) — لجلسات اختبار المستخدمين

صفحة داخلية، **ما فيها رابط من التطبيق**، تقرأ محاولات هذا المتصفح فقط:

1. اكتبي **معرّف المختبر** (مثل `T1`) — بدون أسماء ولا أي بيانات شخصية.
2. المستخدم يجرّب التطبيق. الجدول يعرض لكل موضع في الرحلة (مثل `sujood#1`) عدد المحاولات
   ونتيجة أول محاولة وآخر محاولة ومعدل النجاح، ومعه مقارنة الركعة الأولى بالثانية.
3. **صدّري** (CSV أو JSON) — التنزيل يصير داخل المتصفح نفسه، ولا يُرسل شيء لأي مكان.
4. **"إعادة ضبط للمختبر التالي"** (فيه تأكيد) يمسح المحاولات والمعرّف للجلسة الجديدة.

الحساب نفسه في `src/progress/results.js` (دوال صافية، مختبَرة في `tests/results.test.mjs`).

## قواعد git

- **`main` هو اللي ينشر** على Cloudflare، فلا أحد يدفع عليه مباشرة كود مو مجرب.
- كل وحدة تشتغل على فرعها: `content` و `ai` و `ux` (والنظام على `main` أو فرع `system`).
- **قبل أي دمج:** `npm run build` لازم ينجح، و `npm test` كذلك.
- **ممنوع منعاً باتاً ترفعون:**
  - أي مفاتيح أو ملفات `.env`
  - تسجيلات المستخدمين (صوت أو فيديو)، وهي مستثناة في `.gitignore` تحت `eval/recordings/`
  - صور التجارب
  - أوزان نموذج Whisper، لأنها تتحمل من Hugging Face وقت التشغيل
- لا تضيفون مكتبات جديدة بدون اتفاق الفريق.
